# FINAL SYSTEM ACCEPTANCE — CourseProject V3

Дата приёмки: 13 сентября 2026 года.

Объект проверки: параметрическая система расчёта канала варианта №3 в `/media/sf_OpenFOAM_Labs/CourseProject_V3`.

## 1. Авторитетные требования проекта

Система должна принимать размеры канала и семи квадратных препятствий, проверять их до запуска внешних программ, создавать геометрию и сетку в SALOME, импортировать и проверять сетку в OpenFOAM, последовательно выполнять расчёт без MPI, извлекать численные показатели, строить изображения ParaView и сохранять каждый запуск отдельно. Пользовательский интерфейс должен показывать реальные стадии, итоговые входы и результаты, журнал, завершение и понятную ошибку.

Источники требований: исходное задание курсового проекта варианта №3, локальные методички по интерфейсу/SALOME/ParaView, существующие scripts/cases/logs/results, `settings.json`, `REPORT_DRAFT.md` и первичный аудит `FINAL_REQUIREMENTS_AUDIT.md`. Примеры других студентов использованы только для оценки структуры и функциональной композиции.

## 2. Архитектура параметрического интерфейса

Локальный интерфейс доступен по `http://127.0.0.1:8083/`. Он реализован без сторонних npm-зависимостей:

- `app/public/index.html`, `style.css`, `app.js` — русская форма, SVG-схема, валидация, состояния и результаты;
- `app/server.js` — Node.js HTTP API, изоляция run, запуск фиксированного pipeline и безопасная выдача logs/results;
- `scripts/run_pipeline.py` — SALOME → UNV → OpenFOAM → ParaView → summary;
- `runs/<id>` — неизменяемые каталоги отдельных запусков;
- `/tmp/CourseProject_V3/jobs/<id>` — рабочие каталоги вычислений.

Фактический поток данных:

`UI → POST /api/validate → runs/<id>/settings.json → geometry.py → generate_mesh.py → HDF/UNV → ideasUnvToFoam → transformPoints → checkMesh → parameterize_case.py → sequential SIMPLE/PIMPLE → foamPostProcess → pvpython → summary.json/status.json/logs/screenshots → UI`.

Фиктивные проценты не используются. Стадии берутся из `status.json`: подготовка, SALOME, проверка сетки, подготовка case, решатель, постобработка, сохранение, завершение.

## 7. Тесты D и E — ошибки и восстановление

### D. Некорректный ввод

- `S=5 мм` при `a=12 мм`: «S должно быть не меньше a»;
- пустое `L`: «L: заполните поле»;
- нечисловое `L`: «L: требуется конечное число»;
- действия запуска блокируются до SALOME/OpenFOAM.

### Конфликтующий запуск

Во время активного теста B кнопки были заблокированы. Независимый повторный запрос к серверу получил HTTP 409: «Уже выполняется расчёт web-2026-09-13T19-44-10-248Z. Дождитесь его завершения.» Второй тяжёлый процесс не создан.

Запрос CFD-summary для mesh-only run C отдельно получил HTTP 404 и понятный ответ «Summary ещё не готов». В полном режиме отсутствие ожидаемого `summary.json` после состояния `done` переводится интерфейсом в ошибку, а не маскируется пустыми показателями.

### E. Контролируемый отказ и восстановление

Изолированный сервер использовал отдельный `CPV3_RUN_ROOT=/tmp/cpv3-acceptance-failure-runs` и заведомо завершающийся с кодом 1 процесс. UI показал «Расчётный процесс завершился с кодом 1», перевёл run в `failed` и разблокировал форму. Повторное нажатие было принято и создало новый ID, что подтвердило восстановление интерфейса. Валидированные runs не затрагивались.

Внутри `run_pipeline.py` каждая команда SALOME/OpenFOAM/ParaView проверяется по `returncode`. Любой ненулевой код, включая exit решателя OpenFOAM, вызывает исключение; `main()` записывает `status.state=failed`, текущую стадию и хвост соответствующего журнала. Продолжения к постобработке после такого отказа нет. Отдельный преднамеренный CFD-crash не создавался, поскольку тот же обработчик уже проверен контролируемым exit code 1 и повторный тяжёлый расчёт для этого не требуется.

Полная машинно-читаемая сводка находится в `validation/acceptance_test_results.json`.

## 10. Оставшиеся ограничения

- интерфейс предназначен для локального учебного использования и не реализует многопользовательскую очередь;
- одновременно допускается один тяжёлый расчёт, что намеренно защищает VM с 4 vCPU;
- отмена активного процесса из UI не реализована;
- mesh-only run не содержит CFD summary по определению;
- исследование сеточной независимости и экспериментальная/DNS/LES-валидация не выполнялись;
- URANS-результаты представляют одну секунду нестационарного продолжения, а не долговременную статистику;
- успешность внешних программ зависит от установленного локального SALOME/OpenFOAM/ParaView окружения, но их ошибки теперь явно возвращаются пользователю.

Ограничения документированы и не блокируют сдачу учебного проекта.
